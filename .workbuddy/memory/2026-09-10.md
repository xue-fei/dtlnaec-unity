# 2026-09-10

## AEC 对齐链路优化（近端/远端音频对齐）

重构了 dtlnaec-unity 的 AEC 回声消除近远端对齐逻辑，全链路优化：

### 核心缺陷修复
1. **AlignedLoopbackReader 对齐失效**（最严重）：旧实现 `Pull()` 从未使用 `_delaySamples` 补偿，
   只靠锁定时一次性 `ResetReadPos()`，锁定后读指针退化成普通 FIFO，延迟补偿形同虚设。
   重构为：`Pull` 每帧按 `targetRead = _writePos - _delaySamples` 持续对齐，锁定前后都正确。
2. **读指针竞态**：`_readPos`/`_writePos` 改为 `long` 累计（防回绕），Pull 里 clamp 读指针
   不超过写指针；`_writePos < _delaySamples` 时输出静音不读垃圾数据。
3. **校准反馈循环**：`RunCalibration` 原来用已对齐的 `lpbAligned` 做 GCC-PHAT 延迟估计，
   形成"自己校准自己"的反馈，改为用原始 `rawLpb`。
4. **Push 性能**：逐样本 `foreach` 写改为环形分段 `Array.Copy` 批量写入。

### 性能优化（RuntimeProcessor）
- 预分配复用：`_outputFrame`、`_inBlockFft`/`_lpbBlockFft`、`_fullSpectrum`、`_complexInput`、
  `_estimatedBlockTime`，以及 4 个 `DenseTensor`（`_inMag`/`_lpbMag`/`_estimatedBlockTensor`/`_inLpbTensor`）。
- 消除每帧 `ProcessFrame`/`ProcessBlock` 中的 `new float[]`、`new Complex[]`、`new DenseTensor` 分配。
- 复用 buffer 通过 `EnsureBuffers()` 惰性初始化。

### 关键设计要点（备忘）
- 对齐语义：`readPos = writePos - delaySamples`，正值延迟 = mic 滞后 lpb。
- 对齐判断机制：GCC-PHAT（DelayEstimator.Estimate）算互相关峰值位置 + PHAT 白化，
  输出置信度 confidence = 峰值/均值（peak-to-mean ratio），< 2.0 视为静音/噪声拒绝更新。

### 运行时对齐质量监控（MicCapture）
新增对齐质量监控：每 2 秒汇总置信度/残差，输出质量分(0~100)与状态报告。
- 质量分 = 置信度贡献 60% + 残差贡献 40%
- 残差 = GCC-PHAT 理想延迟与当前补偿延迟的差（samples），对齐良好时趋近 0
- 对外暴露 LastConfidence / LastResidualMs / AlignmentScore 三个属性
- 质量分 < 40 触发告警（提示可能远端静音/延迟漂移/时序错位）

### 实测日志诊断与修复（3 个根因）
实测日志暴露 3 个问题，已修复：
1. **置信度爆炸**（均值飙到 700~940）：`CalculateConfidence` 用有符号 `sum += gcc[i].R`，
   GCC-PHAT 相关序列围绕 0 正负振荡，sum 趋近 0 导致 peak/mean 爆炸甚至负数。
   修复：改用 peak-to-RMS（均方根），恒为正稳定反映本底水平。
2. **静音帧污染**（min=0.00 反复出现）：mic 或 lpb 静音时 PHAT 白化放大噪声成虚假峰。
   修复：Estimate 入口加 RMS 门控（<1e-3 直接返回 0 延迟 + 置信度 0），
   白化加相对 eps 正则化。
3. **残差永不收敛**（25~120ms 抖动，锁定 74.7ms）：`RunCalibration` 误把 GCC-PHAT
   测出的【绝对延迟】当增量叠加（`CurrentDelaySamples + lagDelta`）。
   实际 lagDelta 是 mic 相对「原始 loopback」的绝对延迟，应直接 `UpdateDelay(lagDelta)`。
   同时 CALIB_FRAMES 4096→8192（512ms）减少静音段比例。

### 关键结论（备忘）
- `DelayEstimator.Estimate(mic, lpb)` 返回的是【绝对延迟】（正值=mic 滞后 lpb），
  不是增量。调用方需直接使用，不要叠加到当前值。
- 锁定后 `RunCalibration` 直接 return，`UpdateDelay` 的漂移检测拿不到新测量值——
  这是残留隐患（漂移检测形同虚设），后续需重构为「锁定后仍持续低权重微调」。

### v4 重构：锁定后持续低权重微调（已实现）
彻底重做校准状态机，解决锁定后延迟冻结 + 漂移检测失效的问题：
1. **RunCalibration 锁定后不再 return**：持续累积样本 + 调用 Estimate，
   把新测得的绝对延迟持续喂给 UpdateDelay。
2. **UpdateDelay 锁定后低权重微调**：新增 ALPHA_FINE_TUNE=0.01，锁定后以极低
   权重持续跟踪缓慢漂移（设备切换/蓝牙重连等）。
3. **漂移检测用原始测量值**：clamp（MAX_STEP_SAMPLES=160/10ms）会掩盖真实大漂移，
   导致 drift 永远超不过 LOCKED_MAX_DRIFT(320/20ms)、无法触发解锁。
   修复：保留 rawMeasured 用于漂移判断，微调用 clamp 后的值。
4. 清理死代码：删除 RECALIB_INTERVAL、_recalibCount、prevDelay（均已无引用）。

### 校准状态机最终形态（备忘）
- 锁定前：alpha 从 0.3（前25帧）→ 0.05（后25帧），50 次有效校准后锁定
- 锁定后：alpha=0.01 持续微调；每 100 次校准检查一次漂移，
  原始测量值偏离锁定基准 > 320 samples（20ms）则解锁重校准
- 静音帧：Estimate 入口 RMS<1e-3 门控，直接拒绝（置信度 0），不影响已锁定延迟
- AEC 模型：DTLN-AEC（dtln_aec_128_1/2.onnx），BlockLen=512, BlockShift=128, FftSize=512,
  前 3 帧（PaddingFrames=3）为 zero-padding 预热需丢弃。
- 采样率固定 16kHz，LoopbackCapture 从 Unity 采样率重采样到 16kHz。

### 关键转折：根因是「时钟漂移」而非「信号难测/没回声」（重要结论）
用 1 秒长窗口滑窗互相关分析 mic_raw.wav vs lpb_raw.wav（399232 样本，约 25s），
得出决定性结论，**推翻了之前"mic 没录到回声"的误判**：
1. **延迟是真实存在的、缓慢连续漂移的**：从 -53ms → -25ms → -16ms → +16ms → +138ms
   → +13ms → +37ms，整体趋势是线性漂移 + 周期性跳回（回绕/对齐重排）。
2. **相关系数峰值 0.01~0.16**，偏低是因为「语音信号短时相关性天然弱」（静音间隙多、
   非平稳），不是没回声。长窗口下延迟轨迹高度规律，证明回声真实存在。
3. **根因 = mic(ADC) 与 loopback(DAC) 采样时钟不同步（clock skew）**：两者都标称 16kHz
   但有几十~几百 ppm 差异，导致相对延迟持续漂移。
4. **当前代码的短板**：MAX_STEP_SAMPLES=160(10ms) clamp + 锁定后 ALPHA_FINE_TUNE=0.01
   微调，跟不上这种持续漂移的速度，导致残差周期性反弹（收敛→漂移→跳变）。
5. 正确方向：改「延迟跟踪的响应速度」，让跟踪器能持续跟上线性漂移，而非继续在
   阈值/权重上小修小补。候选方案：锁定后用带速度估计的跟踪（如二阶 Kalman 或
   α-β 滤波）预测并跟随漂移斜率；或直接提高微调权重 + 去掉单帧 clamp 对漂移的阻碍。

### 诊断方法备忘（可复用）
- 纯 Python（无 numpy）分析 WAV：wave + struct 读 16bit PCM，`struct.unpack('<%dh')`。
- 全量 O(n²) 互相关太慢（7 分钟），改用「4:1 降采样 + 分段粗搜索」秒级完成。
- 判断「回声是否存在 + 延迟是否漂移」用 1 秒长窗口滑窗互相关，看延迟轨迹规律性，
  比短窗口（512ms）更抗语音静音干扰。

### v5 优化：α-β 滤波器 + 语音频带加权（数字人语音场景，2026-09-11）
应用背景明确为「数字人语音经扬声器外放，AEC 消除麦克风拾取的数字人声音」。
做两个针对性优化：

**优化1：AlignedLoopbackReader 用 α-β 滤波器替换一阶低通**
- 显式估计延迟漂移速度（_delayVelocity），用「位置+速度」双状态预测下一延迟，
  稳定跟上时钟漂移，消除残差周期性反弹。
- 参数：ALPHA=0.25, BETA=0.05, LOCK_FRAMES=30, MAX_STEP_SAMPLES=160(10ms),
  OUTLIER_REJECT_SAMPLES=480(30ms), OUTLIER_STREAK_RESET=5, 速度限幅 ±8 sample/周期。
- 野值拒绝：残差 > 30ms 跳过更新；连续 5 次野值判定为真实突变（设备切换），重置滤波器。
- 锁定仅用于监控/日志，不再冻结/切换跟踪行为（旧 _lockedStableCount/_lockedLastDelay/
  ALPHA_INITIAL/ALPHA_LOCKED/ALPHA_FINE_TUNE 等字段已删除）。
- 离线 Python 模拟验证：α-β 比一阶低通跟踪误差低 26%~62%（噪声σ=20~40 时）。

**优化2：DelayEstimator 加语音频带加权**
- 数字人语音能量集中 300Hz~4kHz，白化时带外频点按权重衰减（SPEECH_BAND_MIN_WEIGHT=0.05,
  SPEECH_TRANSITION_HZ=500 平滑过渡），让 GCC-PHAT 聚焦有效频段，相关峰更尖锐。
- 实现纯 C#（Clamp01/Lerp 手写），保持 DelayEstimator 不依赖 UnityEngine、可独立单测。

### 技术备忘
- α-β 滤波器适用于「目标近似匀速移动」的跟踪（时钟漂移正是匀速），比一阶低通
  更适合延迟跟踪。参数关系参考雷达惯例 β=α²/(2-α) 保证临界阻尼。
- 当前 BETA=0.05 是经验值，若实测速度跟踪仍偏慢可上调到 0.1~0.15。
